# EAZYstores v2: project status
## Phase D0 (design system): done
Tokens, fonts, icons, art, components, `/_design`, visual-regression harness. Buyer home passes against its references (Atelier, Noir, Sage, dark auto-switch). See `docs/DESIGN.md`.
## Phase 1 (foundation): done
Verified by 20 API integration tests on a real Postgres and by running the CLI and server: migrations (forward-only, idempotent, audit log immutable), buyer sign-up, per-window sign-in with separate sessions and roles, lockout, rate limit, origin check, role grant/revoke with audit and last-admin protection, per-seller permission checks, settings and feature flags with audit, categories and attributes (public tree, inherited attributes, admin CRUD, validation), plain JSON errors.
Not done in this phase (by design, later phases): email verification and password reset (need the email outbox), staff two-factor, sellers/shops/products, orders, payments, search, uploads, push.
## Phase 2 (sellers, shops, catalogue, media, search, demo data): done
Verified by 43 API tests in total (23 new): seller sign-up through the studio window, shop settings, the media pipeline (three WebP sizes, metadata stripped, orientation fixed, disk and database copies, self-healing, Range requests, video conversion with ffmpeg, fake/corrupt/oversize refusals, public vs owner access), drafts with live readiness, publishing rules (required attributes, restricted-category confirmation and review queue, prohibited items, human-hair sourcing), options and variants, one-of-a-kind enforcement (even by raw SQL), made to order, duplicate, bulk edit, per-seller isolation, listing and filters and facets, multi-category membership, search (exact first, verified synonyms, typo fallback, injection-safe), product detail, and the fixed demo catalogue (412 pieces from 38 makers).
Not done here: collections and gift guides, reviews, shipping profiles and delivery estimates (commerce phase), CSV import (studio phase), email and push.
Run `npm run seed:demo -w apps/api` for the demo shops. Seller login: amara@clayember.test (password demo-password-2026).

## Phase 3 (commerce core): done
Verified by 67 API tests in total (24 new, real Postgres): guest and signed-in baskets with merge on sign-in, one-of-a-kind / vacation / sold-out refused at add-to-basket, shipping profiles (flat, per item, weight, free-over) and the per-product delivery estimate, checkout split per seller with exact integer-cent GST and commission, Idempotency-Key replay, a replaced unpaid checkout, the last unit going to exactly one of two parallel checkouts, stock committed on payment and released on failure or expiry, webhook signature check (401), duplicate events applied once, amount mismatch refused, late payment after expiry (stock re-taken, or refunded when gone), 503 when no provider is configured, an append-only double-entry ledger whose unbalanced transactions are rejected at commit, buyer order privacy (no commission shown), seller order flow with tracking and per-seller isolation, partial refunds with exact tax and commission shares (unit by unit adds up to the line), over-refund refused, refund idempotency, provider failure leaving nothing refunded, cancel-and-restock, the email outbox (queued in the same transaction, retried, never sent twice).
Bugs the tests found and fixed: (1) expired orders marked their payment failed, so a provider "succeeded" arriving later was ignored (money taken, order cancelled, no refund); the payment now stays pending until the provider answers. (2) New shops' default shipping profile had a $0 base (silent free shipping); it is now $9.00 flat, 5 to 8 days.
Not done here: a Stripe adapter (only the mock provider exists; production refuses it), real email delivery (a simulated sender is used), payouts, disputes, order screens in the web app (Phases 4 and 5).

## Phase 4 (buyer storefront): done
Built from live API data: home (phone and desktop), category with real filters (price, material, size, handmade, free shipping, more, sort) and "show more", search, product page (photos or illustration, options and swatches, delivery estimate by postal code, personalisation, one-of-a-kind and sold-out states), basket (per-maker groups, delivery windows, quantity, gift note), checkout with a test-mode payment step, order status page, sign in / create account, saved pieces, followed shops, shop page in the shop's look (Atelier, Noir, Sage, Blush, Sky).
Verified: **17 visual-regression screens pass** (all at or under 0.35% differing pixels; the limit is 1.5%): see `docs/DESIGN.md`. `apps/e2e/flow.mjs` drives a real browser through 25 checks: guest buys a piece end to end (add, quantity, gift note, bad postal code refused, GST shown, test payment, order page), a guest is sent to sign in to save, sign-up returns to the page, hearts, saved list, filters in the URL, follow, search and empty search, sign out, desktop navigation and a friendly page for an unknown piece. API: 74 tests pass (7 new: home, curated picks, free-shipping filter, material and size facets, saved pieces, follows, the pinned-clock regression).
Not done: reviews, the "Meet the makers" and gift-guide pages, order chat, real card payments (Stripe adapter), real email, buyer order-history detail beyond the status page, desktop screens other than home have no mockup (built from the same tokens, not pixel-tested). Seller onboarding and the studio are Phase 5.

## Phase 5 (seller onboarding and studio): done
Built: five-step onboarding (what you sell, account, identity and look, photo-first first product with autosave and live readiness, shipping and returns, live with link and QR), studio home (desktop and phone: orders to ship, running low, this week, setup checklist, recent orders), orders (list, detail, accept, ship with tracking, deliver, partial refund, cancel), products (list with search and filters, editor with photos, attributes, options and per-option price and stock, publish, hide, duplicate, delete), shop page settings (identity, logo, banner, look, story, returns, time to ship, vacation), shipping profiles (flat, per item, by weight, free-over), studio sign-in.
Verified: **all 17 reference screens pass visual regression** (the six new ones at 0.10% to 1.18%, limit 1.5%; see `docs/DESIGN.md`; design snapshots unchanged). `apps/e2e/studio-flow.mjs` drives a real browser through **38 checks**: sign-up with a weak password refused, step guards, category suggestion, photo upload and autosave, publish blocked until ready, shop goes live with the entered look and tagline, a buyer's order reaches the seller (badge, home, detail), the seller sees where to ship but not the buyer's email, tracking validation, shipping, partial refund visible to the buyer, delivery, price and stock edits, options with per-option prices, hide and re-publish, vacation mode blocking purchases, a second shipping profile, honest payouts page, friendly unknown-order page. `flow.mjs` (buyer, 25 checks) still passes. API: **79 tests** (5 new for dashboard numbers, checklist, visits, low stock, category suggestion).
Not done: payouts (no payment provider connected), messages, promotions, insights, CSV import, reviews. Studio pages other than home and onboarding have no mockup and are not pixel-tested. Staff consoles are Phase 6.

## Not verified
Nothing in v2 has run on a real device, with Stripe, with real email or with push notifications. Money movement is simulated by the mock provider.
